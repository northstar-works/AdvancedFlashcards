2. KENPO DECK: 0 CARDS + NO EDIT OPTION (Store.kt / WebAppSync.kt / Models.kt)
   Root cause: Store.replaceDecksFromServer() filtered OUT the server's kenpo
   record (filter { it.id != "kenpo" }) and decksFlow() unconditionally
   injected the 0-card KENPO_DEFAULT placeholder with isBuiltIn=true - so the
   UI showed 0 cards, a Built-in chip, and hid the edit controls.
   - replaceDecksFromServer now stores every server deck including kenpo.
   - decksFlow injects the placeholder ONLY when no kenpo record exists yet
     (pre-first-sync).
   - StudyDeck gains canEdit (default true; all existing constructors remain
     valid). Encoded/decoded in Store, parsed in WebAppSync.pullDecks.
   - ManageDecksScreen: action buttons (set-default/edit/delete) now gate on
     (!isBuiltIn && canEdit); read-only server decks show a "Sample" chip;
     switcher-header fallback "?: 88" -> "?: 0".

SERVER-SIDE PREREQUISITES (in the paired server build):
   - GET /api/sync/decks now returns canEdit per deck (owner/admin true).
   - POST /api/sync/decks enforces ownership on metadata updates (a non-owner
     push can no longer rename any deck, kenpo included); new decks pushed
     from Android get ownerId/createdBy = pushing user; the global isDefault
     flag is admin-only.
